# v1.4.6 - Questioning Quagsire

> 🚧 **In development, not recommended for daily use.** Recent releases have shipped real regressions, and this changes the keyboard shortcuts and session behaviour of the desktop it runs beside. Every mistake so far is listed in [`PROVENANCE.md`](https://github.com/Godless-1/omarchy-on-cachyos/blob/main/PROVENANCE.md).

**Questioning Quagsire.** <kbd>Super</kbd>+<kbd>Q</kbd> quits the window — and three checks that were asking the wrong question start asking the right one.

## Quitting

Closing the window was the only way out, which is fine until the window is full-screen and borderless, which is exactly what the KWin rule makes it.

<kbd>Super</kbd>+<kbd>Q</kbd> now ends the session. The key was free — Omarchy 4 binds <kbd>Super</kbd>+<kbd>W</kbd> to close a window and <kbd>Super</kbd>+<kbd>Ctrl</kbd>+<kbd>Q</kbd> to the calculator, and nothing to <kbd>Super</kbd>+<kbd>Q</kbd>, checked against `default/hypr/bindings/` rather than remembered. The bind is added to the generated config *after* Omarchy's own bindings, so it is added rather than overwritten, and only there: a full Omarchy login session is untouched.

It dispatches `hl.dsp.exit()` rather than running a shell command, so the compositor tears its own clients down, and exiting is what triggers the existing cleanup — borrowed <kbd>Meta</kbd>+ shortcuts handed back, PATH shim and temporary config removed, watchdog stopped.

`omarchy-window --print-config` prints the config it would use and stops, touching no KWin rule, borrowing no keys and leaving `XDG_RUNTIME_DIR` empty. The bindings were otherwise only observable by starting a desktop, which no test can do.

## Agent skills

A stock Omarchy install links the skills it ships — `omarchy` and `diagnose-crash`, which `omarchy-agent-crash` depends on — into each agent's config from `omarchy-provision-user`. This project never runs that script, because alongside the skills it rewrites your XDG user directories and `rmdir`s `~/Desktop`, `~/Templates` and `~/Public`. The consequence went unnoticed: an install done this way had no skills at all. The installer links them now, `check`/`fix` handle existing installs, and the uninstaller removes only symlinks pointing into `/usr/share/omarchy`.

Worth stating plainly, because it was the reason the work started: this changes what the agent **knows**, not what it prints. Startup output is byte-for-byte identical with and without them.

## Boot entries

`clean-stale-boot-entries.sh` handled orphaned `/boot/<machine-id>/` directories but not orphaned entries inside `limine.conf` — which is the fault that took a real machine's boot menu apart in 1.4.4. It now reports every top-level entry claiming this machine, names the live one by newest snapshot, and with `--remove-stale-entry` removes the other **by name**, never by machine-ID and position: both entries match the id, so a wrong position removes the one that still boots. On a tie it refuses and says so.

## Three checks that were not checking

**CI built a tag instead of the commit.** The PKGBUILD pins `#tag=v$pkgver`, which exists only once the Release workflow publishes it, so every version-bump commit failed with `fatal: invalid reference`. A red that is always expected is where a real breakage hides. CI now builds the commit in front of it; the release workflow still builds from the real tag.

**A guard against committing build output passed because it could not look.** `git ls-files` on a tarball checkout answers emptily, and "no output" was being read as "nothing tracked". It establishes it can see the repository before believing what it says.

**And it had already failed.** 23 files of makepkg's bare clone were committed in 1.4.5 and only surfaced by breaking `reuse lint`. Asked whether that could happen, the check used was `git add -A --dry-run`, which listed nothing **because the files were already tracked** — `add` reports what it would newly stage. `git ls-files` was the right question and would have said 23. Untracked, ignored, and now guarded mechanically.

## A bug that was never reachable here

`omarchy-window` has never started on a host without `qdbus`. `QDBUS=$(for q in ...; do command -v "$q" ... done)` takes the status of the loop, which is the last failed lookup when none is installed; under `set -e` the script ends on that line before printing anything — while further down offering advice headed "Other desktops:" for people in exactly that position.

It was found because a suite that had only ever run on a KDE machine finally ran somewhere else. That is the through-line of this release: every fault above was found by running the thing somewhere it had not been run before, not by reading it.

Twelve suites, 215 assertions. Code AGPL-3.0-or-later, docs CC-BY-SA-4.0.
