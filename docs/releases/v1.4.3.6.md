# v1.4.3.6 - Stubborn Snorlax

> 🚧 **In development, not recommended for daily use.** Recent releases have shipped real regressions, and this changes the keyboard shortcuts and session behaviour of the desktop it runs beside. Every mistake so far is listed in [`PROVENANCE.md`](https://github.com/Godless-1/omarchy-on-cachyos/blob/main/PROVENANCE.md).

**Stubborn Snorlax.** The install stops needing to be started again.

A second machine got fifteen minutes into the install with 22 of 23 packages downloaded, and then stopped. `pkgs.omarchy.org` reset the HTTP/2 stream on the 114 MiB `omarchy` package, and a CachyOS mirror answered 404 for a file the local database still listed. Nothing was wrong with the machine and nothing needed deciding, but pacman rolls a failed transaction back whole - so the run ended with nothing installed and no explanation. Under `set -e` the script simply exited with pacman's status. The only way on was a human noticing and starting again.

Every pacman transaction now goes through one wrapper that retries while the failure is a download failure: four attempts, five seconds doubling each time. Whatever already arrived stays in `/var/cache/pacman/pkg`, so each attempt resumes rather than restarts. The three failures are not the same failure, and are not treated as one:

- a **404** means the local databases no longer match what the mirror carries, and only a forced `-Syy` fixes that, so one runs before the retry;
- a **reset or a timeout** just needs asking again;
- a **corrupted package** is deleted from the cache first, because otherwise every retry re-validates the same broken bytes.

Anything that is not a download failure - a file conflict, an unknown package, an unsatisfiable dependency - still stops on the first attempt, with pacman's own words and a way out. Asking it four times would only bury the message. When it does give up, it says that nothing is half-installed and that a re-run resumes.

Two smaller things in the same spirit, since the point is a run that does not need anybody watching it: `--disable-download-timeout` on every transaction, so a 20 KiB/s mirror counts as slow rather than dead; and a keepalive holding the sudo timestamp open, so a twenty-minute download is not followed by a password prompt nobody is there to answer.

`docs/troubleshooting.md` gains the failure and the by-hand recovery, and `PROVENANCE.md` records both that the installer used to treat every pacman failure as fatal, and that the new path is tested against a scripted pacman rather than exercised against a mirror that is actually failing.
