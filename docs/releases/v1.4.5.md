# v1.4.5 - Quiet Quagsire

> 🚧 **In development, not recommended for daily use.** Recent releases have shipped real regressions, and this changes the keyboard shortcuts and session behaviour of the desktop it runs beside. Every mistake so far is listed in [`PROVENANCE.md`](https://github.com/Godless-1/omarchy-on-cachyos/blob/main/PROVENANCE.md).

**Quiet Quagsire.** The duplicate-boot-entry check stops shouting about something that is not an emergency.

`v1.4.4` added a check for two top-level boot entries claiming one machine. It worked — it found the fault it was written for on the first machine it ran on. It also reported it as a **failure**, and a failure makes the verdict print `DO NOT REBOOT` in red. Directly beneath that, the finding's own text read *"Booting is not at risk meanwhile - the current entry still works."*

Both halves came from the same commit, and they contradict each other. The live entry boots; that is how the machine reporting the fault was running at the time. A checker whose loudest signal is wrong is worse than one that stays quiet, because the next time it says `DO NOT REBOOT` nobody will believe it.

It is a warning now. The verdict says `No failures` and prints the recovery steps, which is what a non-blocking finding deserves. Nothing about the detection changed — same rule, same fixtures.

A test now asserts the severity directly: it reads the branch out of `verify-reboot-safety.sh` and fails if it calls `bad()` instead of `warn()`. That assertion was checked the only way an assertion can honestly be checked — by reintroducing the bug and confirming the suite went red, then putting it back.

This is the third time in this project's history that the boot verifier has been wrong in the alarming direction rather than the quiet one: a false `DO NOT REBOOT` after a good rebuild, four confident failures on an intact machine, and now this. All three are in [`PROVENANCE.md`](https://github.com/Godless-1/omarchy-on-cachyos/blob/main/PROVENANCE.md#mistakes-made-and-corrected). The pattern is worth naming: the code that exists to tell you whether your machine is safe has been the code most likely to be confidently wrong about it.

Nine suites, 163 assertions. Code AGPL-3.0-or-later, docs CC-BY-SA-4.0.
